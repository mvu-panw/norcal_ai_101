H100

NVIDIA's Hopper-generation data center GPU and the workhorse of the first generative AI wave. It introduced the Transformer Engine and FP8 precision. Comes as SXM (on an HGX board), PCIe, and H100 NVL (two PCIe cards bridged).

80 GB HBM3 · 3.35 TB/s · NVLink 900 GB/s · up to 700 W (SXM) · 80 billion transistors

H100Hopper architecture

H200

A Hopper GPU with the same compute as H100 but more and faster memory (HBM3e), so larger models and longer contexts fit on fewer GPUs. The H200 NVL version is a lower-power, air-cooled PCIe card.

141 GB HBM3e · 4.8 TB/s (1.4x H100) · NVLink 900 GB/s · up to 700 W

H200

B200

The first Blackwell GPU. Every Blackwell GPU is two reticle-limited dies joined by a 10 TB/s chip-to-chip link so they act as one GPU. It added FP4 precision. Ships in HGX/DGX B200 (8 GPUs) and in GB200 Superchips.

208 billion transistors (TSMC 4NP) · 180 GB HBM3e in DGX B200, 186 GB in GB200 · 8 TB/s · NVLink 1.8 TB/s

Blackwell architectureDGX B200

B300 (Blackwell Ultra)

The mid-generation upgrade to Blackwell, built for reasoning and test-time scaling: more memory per GPU and more FP4 throughput. Ships in HGX B300 (8 GPUs) and the GB300 NVL72 rack.

279 GB HBM3e, 8 TB/s, up to 1,400 W (GB300) · 270 GB, 7.7 TB/s, up to 1,100 W (HGX B300) · 20 PFLOPS FP4 sparse / 15 dense

GB300 NVL72HGX

Rubin GPU

NVIDIA's 2026 GPU generation, the successor to Blackwell. It moves to HBM4 memory, sixth-generation NVLink, and a new Transformer Engine with adaptive compression for NVFP4. Paired with the Vera CPU.

288 GB HBM4 · 19.2 TB/s · NVLink 3 TB/s · 50 PFLOPS NVFP4 inference (projected)

Rubin platformVera Rubin NVL72

SXM vs. PCIe form factor

SXM is a socketed GPU module that mounts on a baseboard (like HGX), gets full NVLink bandwidth and higher power limits. A PCIe card plugs into a standard server slot; it's easier to deploy but slower to talk to other GPUs (PCIe Gen5 is 128 GB/s vs. 900 GB/s NVLink on H100).

H100 SXM up to 700 W vs. H100 PCIe 300–350 W

H100 specs

L40S and L4

PCIe GPUs for inference, graphics and video in standard air-cooled servers, not large-scale training. They use GDDR6 memory instead of HBM and have no NVLink.

L40S: 48 GB GDDR6, 864 GB/s, 350 W · L4: 24 GB, 300 GB/s, 72 W, low-profile single slot

Source: NVIDIA L40S and L4 datasheets

CPUs & Superchips

In an AI system the CPU runs the operating system, feeds the GPUs, and handles tokenization, scheduling and data prep. NVIDIA's own Arm CPUs pair with its GPUs over a coherent link to form "Superchips."

Grace CPU

NVIDIA's Arm-based data center CPU, built with LPDDR5X memory for high bandwidth at low power. Appears as the CPU half of GH200, GB200 and GB300 Superchips.

72 Arm Neoverse V2 cores per CPU · Grace CPU Superchip: 144 cores, up to 1 TB/s memory bandwidth, 500 W

Grace CPU

Vera CPU

Grace's successor, paired with Rubin GPUs. NVIDIA positions it for agentic AI, reinforcement learning and data processing.

88 custom NVIDIA Olympus cores (176 threads) · up to 1.5 TB LPDDR5X

HGX / Vera

Superchip

A single module combining NVIDIA CPUs and GPUs over NVLink-C2C, so the GPU can use CPU memory as an extension of its own.

GH200 = 1 Grace + 1 Hopper · GB200 = 1 Grace + 2 Blackwell · GB300 = 1 Grace + 2 Blackwell Ultra · Vera Rubin = 1 Vera + 2 Rubin

GB200Vera Rubin

GH200 Grace Hopper

The first Superchip: one Grace CPU and one Hopper GPU. The GPU can reach up to 624 GB of fast memory (HBM plus the CPU's LPDDR5X), which helps memory-hungry inference.

96 GB HBM3 or 144 GB HBM3e · up to 480 GB LPDDR5X · NVLink-C2C 900 GB/s

Source: NVIDIA GH200 datasheet

NVLink-C2C

"Chip-to-chip" NVLink: a memory-coherent link between a CPU and GPU (or two Superchips). Coherent means both sides see the same memory without copying data back and forth.

900 GB/s on Grace-based Superchips, about 7x PCIe Gen5 · 1.8 TB/s per Vera Rubin Superchip

NVLink-C2C

Systems & Clusters

How GPUs are packaged, from an 8-GPU server up to thousands of GPUs. The unit of compute keeps growing: from the chip, to the server, to the rack, to the whole data center.

HGX

NVIDIA's 8-GPU baseboard with NVLink Switch chips on board. Server makers (Dell, Supermicro, HPE and others) build their own servers around it.

HGX H100/H200, B200, B300, Rubin NVL8 · HGX B300: 14.4 TB/s NVLink Switch bandwidth · HGX Rubin NVL8: 2 TB HBM4, 24 TB/s

HGX

DGX

NVIDIA's own-brand, fully integrated AI systems: hardware, networking and the DGX software stack, sold and supported by NVIDIA. DGX systems are the building blocks of BasePOD and SuperPOD.

DGX H100: 8x H100, 640 GB GPU memory, 10.2 kW · DGX B200: 8x B200, 1,440 GB, 14.4 TB/s NVLink, ~14.3 kW, 8x ConnectX-7 at 400 Gb/s

DGX B200

NVL72

A liquid-cooled rack with 72 GPUs and 36 CPUs in one NVLink domain, so the rack acts as a single giant GPU. "NVL72" means 72 GPUs on NVLink. Generations: GB200 NVL72, GB300 NVL72 and Vera Rubin NVL72.

GB200: 13.4 TB HBM3e, 130 TB/s NVLink · GB300: 20 TB HBM3e, 130 TB/s · Vera Rubin: 20.7 TB HBM4, 216 TB/s, 3.6 EF NVFP4

Compute tray

One server node inside an NVL72 rack. A GB200 rack has 18 compute trays, each with two GB200 Superchips (4 GPUs + 2 CPUs), four ConnectX-7 NICs for the compute fabric, and two BlueField-3 for in-band management and storage.

18 trays x 4 GPUs = 72 GPUs

GB200 SuperPOD RA

DGX BasePOD

A reference architecture for building an enterprise AI cluster from DGX systems, partner storage and NVIDIA networking. It's a validated blueprint, not a single product.

DGX BasePOD

DGX SuperPOD

NVIDIA's turnkey AI supercomputer: compute, networking, storage, software and services delivered as one product and built from Scalable Units. Deployed on-premises or in a colocation facility, with the customer owning the hardware.

GB200 SuperPOD scales to 128+ racks and 9,216 GPUs

DGX SuperPOD

Scalable Unit (SU)

The repeatable building block of a SuperPOD. You grow a cluster by adding SUs, and the network is designed for full SUs even when partly filled.

GB200 SU = 8 NVL72 racks = 576 GPUs

GB200 network fabrics

AI factory

NVIDIA's term for a data center built to produce intelligence, measured in tokens. Success is measured in tokens per second, per watt and per dollar. An AI factory usually serves one owner's giant jobs, while an AI cloud serves many tenants.

NVIDIA glossary

Liquid cooling

Coolant piped directly to cold plates on the chips. Rack-scale systems like NVL72 need it because air can't remove that much heat from one rack. It also lets GPUs sit closer together, which shortens NVLink cables.

GB300 NVL72: fully liquid-cooled · B300 up to 1,400 W per GPU

GB200 NVL72

Scale-Up Interconnect

Scale-up connects GPUs so tightly that they behave like one bigger GPU (inside a server or rack). Scale-out connects many of those systems over a network. Scale-across links whole data centers.

NVLink

NVIDIA's direct GPU-to-GPU interconnect. It's far faster than PCIe and lets GPUs read each other's memory, which is what splitting a model across many GPUs depends on.

H100 NVLink 900 GB/s is about 7x PCIe Gen5

NVLink

NVSwitch / NVLink Switch

A switch chip for NVLink traffic. It gives every GPU a full-speed path to every other GPU (all-to-all, non-blocking). On HGX boards the chips sit on the baseboard; in NVL72 they sit in dedicated switch trays.

GB200 NVL72: 9 switch trays x 2 chips = 18 chips; each GPU has one NVLink 5 link to each of the 18

NVLink SwitchGB200 RA

NVLink domain

The set of GPUs that can all reach each other over NVLink. Inside the domain, GPU-to-GPU traffic never touches the slower data center network. A bigger domain fits bigger models.

8 GPUs (HGX) → 72 GPUs (NVL72)

GB200 NVL72

Multi-Node NVLink (MNNVL)

NVIDIA's documentation name for rack-scale systems like NVL72, where NVLink spans multiple compute trays through NVSwitches and a passive backplane, instead of staying inside one server.

MNNVL user guide

SHARP

Scalable Hierarchical Aggregation and Reduction Protocol. The switch itself does the math for collective operations (like summing gradients from every GPU), so less data crosses the network. Available in NVLink Switch and InfiniBand switches.

InfiniBand

PCIe

The standard expansion bus that connects GPUs, NICs and storage to the CPU. It's universal but much slower than NVLink, so GPU-to-GPU traffic avoids it where possible.

PCIe Gen5 x16: 128 GB/s · ConnectX-8 adds PCIe Gen6

H100 specs

Scale-Out Networking

The networks that connect servers and racks. A GB200 SuperPOD uses five fabrics: NVLink 5, compute, storage, in-band management and out-of-band management.

North-south vs. east-west

North-south traffic enters and leaves the data center (users, APIs, the internet). East-west traffic moves between servers inside it, mostly GPU-to-GPU. AI clusters are dominated by east-west traffic.

Prompt Journey →

Compute fabric

The dedicated GPU-to-GPU network between servers or racks, used for distributed training and large inference jobs. It's lossless, low-jitter and usually rail-optimized: the same-numbered NIC in every server connects to the same leaf switch, so most traffic is one hop away.

GB200 SuperPOD: rail-optimized, non-blocking fat tree on NDR 400 Gb/s InfiniBand

GB200 network fabrics

In-band and out-of-band management

In-band: the everyday network for SSH, DNS, job scheduling, home directories and container registries. Out-of-band (OOB): a separate network to each server's BMC for remote power, serial console and sensors. It works even when the server's OS is down.

SuperPOD network fabrics

InfiniBand

A lossless, low-latency network built for HPC and AI, with in-network computing (SHARP), adaptive routing and congestion control. It's the traditional choice for single-owner AI factories. NVIDIA's InfiniBand switch families are called Quantum.

Speeds: HDR 200 → NDR 400 (Quantum-2) → XDR 800 Gb/s (Quantum-X800)

NVIDIA InfiniBand

Quantum-X800

NVIDIA's 800 Gb/s InfiniBand platform for Blackwell- and Rubin-era clusters. The Q3400-RA switch was the first to use 200 Gb/s-per-lane SerDes.

Q3400-RA: 144 ports at 800 Gb/s in 4U

Source: NVIDIA Quantum-X800 solution overview

Spectrum-X Ethernet

NVIDIA's AI-tuned Ethernet: Spectrum-X switches plus SuperNICs, with RoCE, adaptive routing and congestion control. It's built for multi-tenant AI clouds and uses standard Ethernet (supports SONiC). Spectrum-XGS extends it across data centers.

NVIDIA claims 1.6x AI network performance over off-the-shelf Ethernet · multiplane designs up to 128K GPUs in two tiers

Spectrum-X

RDMA and RoCE

Remote Direct Memory Access lets one machine read or write another's memory without involving either CPU or making extra copies. InfiniBand is RDMA-native. RoCE (RDMA over Converged Ethernet) brings RDMA to Ethernet.

SuperNIC / RoCE

GPUDirect (RDMA and Storage)

Lets NICs and storage move data straight into GPU memory, skipping the CPU and system-memory copies. NVIDIA cites up to 10x better performance for GPUDirect RDMA.

GPUDirect

ConnectX SuperNIC

NVIDIA's high-speed network adapters. A SuperNIC is a ConnectX tuned for GPU-to-GPU AI traffic, typically one per GPU on the compute fabric.

ConnectX-7: 400 Gb/s · ConnectX-8: 800 Gb/s, PCIe Gen6 · ConnectX-9: up to 1.6 Tb/s per GPU

SuperNIC

BlueField DPU

A Data Processing Unit: a NIC with its own Arm cores that offloads networking, storage and security from the host CPU and isolates tenants. It's a natural place for infrastructure security in multi-tenant AI clouds.

BlueField-3: 400 Gb/s · BlueField-4: up to 800 Gb/s, ships with Vera Rubin

BlueField

Memory & Compute

The numbers on every datasheet. For inference, memory capacity and bandwidth often matter as much as raw FLOPS.

HBM (HBM3, HBM3e, HBM4)

High Bandwidth Memory: DRAM stacked vertically and placed right next to the GPU die. It holds the model weights and KV cache, and its bandwidth sets the speed limit for generating tokens.

H100 HBM3 3.35 TB/s → H200 HBM3e 4.8 → B300 HBM3e 8 → Rubin HBM4 19.2 TB/s per GPU

H200Vera Rubin

LPDDR5X

Low-power server memory attached to Grace and Vera CPUs. It's slower than HBM but far larger and cheaper, and GPUs can reach it over NVLink-C2C. That's why GB300 NVL72 lists "37 TB of fast memory" but only 20 TB of HBM.

Source: GB300 NVL72 and GH200 datasheets

Tensor Core

Specialized units inside the GPU for matrix math, the core operation of neural networks. Each generation adds lower-precision formats for more throughput.

Blackwell: fifth-generation Tensor Cores with microscaling formats

Tensor Cores

Transformer Engine

Hardware and software that switches precision layer by layer during training and inference to keep accuracy while using faster, smaller number formats. Introduced with Hopper (FP8), extended to FP4 on Blackwell and NVFP4 with adaptive compression on Rubin.

Blackwell architecture

Precision: FP16, FP8, FP4, NVFP4

How many bits store each number. Fewer bits means less memory, more throughput and lower power, at some accuracy risk. NVFP4 is NVIDIA's 4-bit format that uses fine-grained scaling to keep accuracy.

GB300 per GPU: 5 PFLOPS FP16 → 10 FP8 → 20 FP4 (sparse)

Tensor Cores

FLOPS, petaFLOPS, exaFLOPS

Floating-point operations per second. Peta = 1015, exa = 1018. Always check the precision and whether the figure is sparse or dense. Sparse figures assume half the values are zero and are usually 2x the dense ones.

GB300 NVL72: 1.44 EF FP4 sparse, 1.08 EF dense

Source: GB300 NVL72 datasheet

TDP

Thermal Design Power: the maximum power a chip is designed to draw and the cooling system must remove. Rising TDPs are why AI racks need liquid cooling and new power designs.

L4 72 W · H100 SXM 700 W · B300 (GB300) up to 1,400 W

Source: NVIDIA datasheets

MIG (Multi-Instance GPU)

Splits one physical GPU into as many as 7 isolated instances, each with dedicated compute, memory and cache, so small jobs or tenants can share a GPU safely.

GB200 example: 2 x 93 GB, 4 x 46 GB or 7 x 23 GB · H100: up to 7 x 10 GB

MIG

KV cache

The model's working memory of a conversation: stored attention keys and values for every token so far. It lives in HBM, grows with context length, and is what prompt caching reuses.

Software & Operations

The software that makes the hardware usable, from the programming model to running a whole AI factory.

CUDA

NVIDIA's parallel programming platform and the foundation of its software ecosystem. Frameworks like PyTorch run on GPUs through CUDA and its libraries.

CUDA

NCCL

NVIDIA Collective Communications Library, pronounced "nickel." It runs the collective operations (all-reduce, all-gather, broadcast) that multi-GPU jobs depend on. It detects the topology automatically across PCIe, NVLink, NVSwitch, InfiniBand and RoCE.

NCCL

TensorRT-LLM

An open-source library that optimizes LLM inference on NVIDIA GPUs (kernels, quantization, in-flight batching). vLLM and SGLang are popular alternatives.

TensorRT

NVIDIA Dynamo

An open-source, distributed inference-serving framework for multi-node deployments. It's known for disaggregated serving: running prefill and decode on separate GPU pools.

Dynamo

NIM

NVIDIA Inference Microservices: prepackaged containers that serve a model behind a standard API, with optimized inference engines built in.

NIM

DCGM

Data Center GPU Manager: monitors GPU health, utilization and diagnostics across a cluster. DCGM-Exporter feeds the metrics to Prometheus and Grafana, including in Kubernetes.

DCGM

Slurm and Kubernetes

The two common workload managers. Slurm is the HPC-style batch scheduler favored for large training jobs. Kubernetes orchestrates containers and dominates inference serving, using GPU operators to expose GPUs.

Source: NVIDIA AI Infrastructure and Operations course, Unit 13

Base Command Manager (BCM)

NVIDIA's cluster management software: provisioning, OS and firmware updates, user access, deploying Slurm or Kubernetes, and monitoring. Now available free, with optional enterprise support.

Base Command Manager

Mission Control

NVIDIA's AI factory operations suite. It builds on BCM and adds rack-scale provisioning for NVL72, liquid-cooling integration, health validation, and automatic recovery from job and hardware failures.

Mission Control
