The Prompt Journey

What happens between typing a prompt into Claude Code and seeing index.html appear on your laptop.

The key idea: Claude Code runs on your laptop. The model runs in a data center. The model never touches your laptop. It sends back requests to read or write files, and Claude Code carries them out locally, with your permission.

Step by step

  1. You type a prompt. "Make a one-page static site for this AI 101 session with an agenda and a countdown timer."
  2. Claude Code packages it. Your few words become thousands of tokens. The package includes Claude Code's own instructions, a description of every tool it can use (Read, Write, Edit, Bash, and others), your project's CLAUDE.md, and the conversation so far. Run /context to see the total.
  3. It goes to the data center. The request is sent as an encrypted HTTPS POST to Anthropic's API. After authentication and rate limiting, it lands on a cluster that serves the model.
  4. The model reads, then writes. The text is split into tokens. The model reads all of them in one parallel pass (prefill), then generates its reply one token at a time (decode), streaming each token back as it's produced.
  5. The reply is a tool call, not a file. Instead of plain text, the model returns a structured tool_use block: "call Write with this path and this content."
  6. Your laptop does the work. Claude Code asks your permission, writes the file to your disk, and sends the result back as a new request. That new request includes everything from step 2 plus the latest exchange.
  7. Repeat until done. The loop continues until the model answers in plain text with no more tool calls. Even a "simple" site can take several round trips.

What actually goes over the wire

The request (simplified)

{
  "model": "claude-...",
  "stream": true,
  "system": "You are Claude Code... // + CLAUDE.md",
  "tools": [
    { "name": "Write", "input_schema": {...} },
    { "name": "Read",  ... },
    { "name": "Bash",  ... }
  ],
  "messages": [
    { "role": "user",
      "content": "Make a one-page static site..." }
  ]
}

The reply (simplified)

{
  "role": "assistant",
  "content": [
    { "type": "text",
      "text": "I'll create the page." },
    { "type": "tool_use",
      "name": "Write",
      "input": {
        "file_path": "index.html",
        "content": "<!DOCTYPE html>..."
      } }
  ],
  "stop_reason": "tool_use"
}

Claude Code then sends a tool_result ("file created") in the next request, and the loop continues.

The exact steps vary from run to run. The model decides which tools to call based on what it sees.

Stays on your laptop

  • Your files, until a tool reads one
  • Running the tools: writing files, running commands
  • Permission decisions (you approve each action)

Goes to the data center

  • Your prompt and the whole conversation
  • Claude Code's instructions, tool definitions, and CLAUDE.md
  • The contents of any file the model reads
  • The output of any command it runs

For a security audience, this is the key question: anything a tool reads becomes part of the prompt. Claude Code data usage

Why resending everything isn't as wasteful as it sounds

Every round trip resends the whole context, which can be tens of thousands of tokens. Reprocessing all of it each time would be slow and expensive.

Prompt caching fixes this. The data center keeps the model's working memory of the unchanged beginning of the request (the KV cache) and reuses it on the next turn, so only the new tokens need full processing. prompt caching docs
